Parallel hyperparameter optimization for stochastic simulations

Aster is an open-source research library investigating adaptive replication allocation: how to reduce simulation work while preserving the quality of the selected configuration.

Research prototype · Ken Cheng · Python / MIT license

Research approach

Parallel evaluation
Independent replications run across local worker processes.
Adaptive allocation
Matched comparisons guide which configurations receive more work.
Independent audit
Evaluate the selected configuration with a separate seed namespace.

Reproduce the example

Clone the repository and run the synthetic comparison locally. A laptop with two available CPU workers is enough for this example.

Install from source · macOS / Linux 
git clone https://github.com/kenchengkc/aster-hpo.git
cd aster-hpo
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
python examples/noisy_quadratic.py --workers 2

The example writes JSON to results/smoke/, then exits. This website displays saved files; visiting it does not start a computation.

Method and implementation

Design notes ↗

A small research runtime built around one question: which configuration should receive the next replication?

  1. Sample

    Generate a candidate pool from typed search spaces.

    sample_configs()

  2. Allocate

    Continue or prune candidates at replication checkpoints.

    Study + scheduler

  3. Execute

    Evaluate objectives in local worker processes.

    ProcessPoolExecutor

  4. Audit

    Lock the selection, evaluate new seeds, and export results.

    audit() · result.save()

Statistical boundaries

ReplicationRace uses a heuristic pruning rule based on paired outcomes and a standard-error margin. Repeated inspection and adaptive peer selection mean this is not a formal confidence-sequence guarantee. Audit statistics are descriptive; they are not a non-inferiority test.

Implementation details and current limits

Training, shared-scenario, and audit randomness use separate seed namespaces. JSON exports include observations, pruning decisions, timing, and failures. Exceptions and non-finite losses fail the affected trial.

The current implementation has no distributed executor, persistent checkpoints, automatic retries, or deadlines. The v0.1 snapshot was verified with 37 tests; current CI results are on GitHub.
